# 自动地图生成算法 v2

日期：2026-11-09。

本文记录 v2 首轮实现与当时的验收结果。后续默认版本、统一占地及实图补环复核，以 `map-generation-algorithms-v3-20261109.md` 为准；已有 v1/v2 配方仍保留对应算法。

本轮目标是提高生成的可控性、碰撞判断的准确性和参数恢复的可信度，而不是增加新的地图类型，也不是承诺所有地图生成得更快。地图文件格式、原生素材审核规则、保存语义和单次撤销流程均保留。

## 使用与兼容

- 生成窗口的“生成算法”可选择“优化算法 v2”或“兼容算法 v1”；快捷创建中位于高级生成设置。
- 全新窗口和内置生成模板使用 v2。没有算法字段的旧配方、旧参数和旧预设按 v1 恢复，不自动升级。
- 算法版本写入 `Parameters.AlgorithmVersion`；v2 配方的 `GeneratorVersion` 另带 `/algorithm-v2` 标识。未知版本明确拒绝。
- 仅调整密度等部分参数，不切换算法。尚未加载素材时返回上一步，也保留已选择的算法。
- 公共生成器 API 的 `TerrainOptions`、`ProvinceOptions`、`TempleOptions` 默认仍为 v1；显式设置 `AlgorithmVersion = 2` 才采用新策略。
- 同一种子跨算法版本不承诺生成相同地图；在相同算法版本、参数、布局约束、素材与运行环境下检查确定性。

## 六项算法调整

### 1. 真正的方形占地净空

`MapClearance` 从右下向左上动态规划，求出以每个格为左上角、完全位于地图内且不含两种原生碰撞位的最大轴对齐正方形。

路线分析允许选择 1–64 格的方形边长。寻路只访问能容纳整个占地的位置，并报告所选最短路线上的最小方形净空。路线点是占地左上角锚点，不是物件中心点。

原有“狭窄格”仍表示邻格连接度，未偷换为宽度；已有布局约束仍按单格规则检查。分析 2×2 占地不可达而单格约束通过，并不矛盾，界面明确区分。这里没有模拟服务端移动、斜向移动或真实角色模型。

### 2. 独立随机域与稳定候选

- 将省域特征、地表参数、边界选择以及地牢布局、内部墙岛、地板纹理分开取随机数。
- 内部树、灌木、岩石的候选位置、接受概率和素材选择由种子、用途域、坐标与取样编号确定。
- 纹理变体和省域素材候选使用稳定排序；地板修补不会消耗另一块地板的随机序列。
- 新增物件确实占用了空间时，后续物件可以发生必要变化；不承诺“增加一棵树，附近所有装饰仍完全不变”。

### 3. 约束提前参与预留

`GenerationConstraints` 将必需净空区与必需通行区编译成装饰预留掩码，但保留二者的区别：无物件不代表可通行。

省域在原生地表与水岸完成后，寻找并预留必需路线的全部格及缓冲带，再布置悬崖、聚落和植被。会与封闭边界冲突的必需区域或路线点，在地表生成前报出名称与坐标。地牢在原生墙体完成后先检查硬条件、预留通路，再布置主题装饰。地表生成保留最终结构检查，且不会为小选区分配整张大地图的预留数组。

这不是自动开路求解器。若既有水岸、墙体或封闭边界与硬条件不兼容，仍明确拒绝该种子；不拆除原生结构、不把净空当作可通行，也不静默忽略条件。偏好条件仍只提示，保护区仍用于局部生成。原有最终检查继续作为独立复核。

### 4. 按绕行收益选择普通地牢回路

普通经典地牢保留原有连通骨架。新增连接不再单纯以 25% 概率接受，而是在有限候选中评估房间图的两两最短路缩短量。

以原骨架中确定的一对直径端点作为主干参考，要求补环后的主干距离不低于原来的 75%。没有符合条件的有益连接时不强行补环。这里的距离是无权房间图边数，不是最终地图路径格数，也不是玩家通关时间。主题地牢的专有拓扑和洞穴主体构造未被替换。

### 5. 与实际碰撞占地有关的生态间距

保留现有林丛密度、空地、林缘、路肩和水岸亲和度。内部候选以稳定优先级排列，使用空间桶做变半径排斥；半径根据物件碰撞占地计算，不把高大的树冠图卡当作同样大的碰撞体。

仍使用完整原生物件、已有地表匹配和碰撞检查。这个实现是确定性的候选散布与局部排斥，不是对连续空间 Poisson-disk 最优性或森林美观程度的证明。

### 6. 少改动的原生角点传播

对不支持的对角形状 6/9，每次只填充或裁剪一个顶点，优先选择产生更少邻域冲突的修改，并只重新检查受影响的相邻格。填充只在许可区域内进行，修改方向单调，因此修改次数受顶点数限制。

这不是全图 WFC，也不声称得到全局最小修改解。三材质交点、缺少审核过渡或缺少素材形状仍明确拒绝，未添加未审核的拼片。

## 复现链路的配套修正

v2 的布局约束会影响生成结果，因此候选身份不能只有“种子和控件参数”。

- 候选保存防御性复制的布局快照；同种子、同参数、不同布局约束不会命中旧候选。
- 恢复候选时，同时恢复设计模型、编辑器与生成器约束快照；原有收藏保护仍保留。
- 批量结果也保存搜索时的布局快照，恢复旧结果不会误用当前已修改的约束。
- A/B 对比会明确提示布局约束不同；失败提示保留原始原因，不再被通用素材恢复提示覆盖。

## 可独立复核的验证

### 独立算法预言机

- 穷举 4×3 地图的 4,096 种碰撞布局，将净空结果与逐位置、逐占地的直接枚举比较。
- 对同一组布局，以独立占地碰撞与队列搜索检查 1×1、2×2、3×3 路线可达性及最短距离。
- 穷举 3×3 顶点场的 512 种状态，分别检查填充与裁剪的合法形状、单调性、确定性和幂等性。
- 用独立 BFS 房间图距离验证补环后的连通性、绕行改善及主干距离下界。
- 用全量两两距离检查核对空间桶间距判断，并验证候选坐标不因预览尺寸或其他随机域的使用而漂移。
- 检查超过 4,096 格的路线仍完整预留，而不是错误地使用仅供绘图的采样路径。

### 固定种子微基准

`MapGenerationBenchmarkTests` 使用 12 个固定种子，256×256 地图，分别运行地表、省域、地牢的 v1/v2，共 72 次。每类先预热，交替版本运行顺序，记录生成与物化耗时、当前线程分配字节数和最终原生碰撞指标。

这些是小样本观察，不是独立视觉验收集。省域使用合成单格植被，未加载真实客户端水岸和图卡。P95 使用最近秩，12 个样本时就是该组最大值；分配字节数不是峰值内存。本轮不能据此宣称全面提速。

原始数据：`Build/Reviews/algorithm-v2/seed-benchmark.json`。
