# 从地图批量拆分模块：通道拆分与候选模块选择方案

状态：阶段 17～20 已实施并完成定向验收（2026-11-06）。下文保留原规划及分析依据；实施细节和验收见 `module-generation-stages.md`。

最终真实地图结果：参考 48×32，通道模式 64 个候选、33 个可用，覆盖 7,453 个原图通行格；修复后的固定网格为 35 个候选、12 个可用，覆盖 4,059 个通行格。33 个模块可批量入库，并生成 12 个实例的 98×98 新地图。未能入库的 31 块仍显示原因，源图不被修改。

兼容实现补充：新增可选 `connections.mapGroundGrid` 标记源图网格相位；仍使用目录版本 1、原 `.X` 格式及原 `footprint`。这是为保留旧对象奇数局部坐标的自动对齐行为，同时避免把源图非显示格的引用意外变为显示图片。旧记录无需迁移。

交互边界：移动切线支持两个矩形的完整公共边，T 形交接先合并再调整；一次合并两个相邻矩形。自动保护已知对象元数据，不能从任意素材图片识别完整建筑。随机结果不自动补墙或封口。

实施位置：`D:/Code/Mir`，分支 `codex/automatic-module-generation`。沿用现有“从地图批量拆分模块”入口，保留之前的改动和 stash。

## 真实地图发现

`632.map` 为 200×200，共 40,000 格。以模块生成实际使用的碰撞规则和四邻域分析：

| 项目 | 结果 |
|---|---:|
| 可通行格 | 7,509 |
| 主通路 | 7,504 格 |
| 其他通行区域 | 3 处，共 5 格 |
| 无素材内容但可通行 | 3,567 格 |
| 偶数 X／偶数 Y 格的非零地面图片引用 | 9,996 |
| 其他奇偶位置的非零地面图片引用 | 10,218 |

三处小岛位于 `(157,44)`、`(167,55)`、`(122..124,109)`。不能把无素材格默认为阻挡，否则会损坏原地图的大量通路。

48×32 网格复现了 35 块全部不可用：22 块被地面对齐检查拒绝，13 块没有可用接口。当前 `ModuleGeneration.Prepare` 要求所有非零地面图片引用具有同一种坐标奇偶性，而源文件在其他奇偶位置也保存了图片引用；相关渲染代码只在对应偶数地面格绘制。应先审查这两种语义的兼容性，不能把所有失败归咎于切口。

仅在内存副本中屏蔽非绘制位置的地面图片引用、保留碰撞位后，对照结果如下：

| 分块尺寸 | 原始数据可用数 | 对照副本可用数 | 总块数 |
|---|---:|---:|---:|
| 48×32 | 0 | 12 | 35 |
| 32×32 | 0 | 22 | 49 |
| 48×48 | 0 | 10 | 25 |
| 64×64 | 0 | 4 | 16 |

对照仅证明兼容性是首要阻碍，不构成正式修复，也没有验证真实素材渲染完全等价。正式实现不能直接照搬“清除引用”操作，必须核对地图读取、地面渲染、`.X` 裁剪平移及保存重开语义，优先保留原始数据。源文件分析前后 SHA-256 均为 `A1AAE49399A94F5EC4E21A47A76222D1A58A17D3E5177D7D4F62BCC7835EA347`。

## 用户流程

选择 `.map` → 查看碰撞与通路诊断 → 选择“按通道拆分” → 查看候选模块 → 选择、调整切口或合并 → 入库并随机生成新地图。

- 原窗口增加“固定网格 / 按通道”模式，不增加新的主菜单入口。
- 首次分析同时展示可通行区域、实际错误位置和推荐切口。存在问题时区分地面兼容、孤立通路、切口不合法及接口不匹配。
- 模块列表显示缩略预览、占地、接口、可用状态与原因。模块类型可标为直道、转弯、岔路、尽头或未分类；类型只是建议，不作为保存正确性的依据。
- 点击列表或画布选择同一模块；勾选只决定是否入库。支持选择可用模块、取消选择、定位问题。
- 用户可以查看任意通行区域；默认聚焦最大区域，其他区域仍明确显示，不默默删除、不修改碰撞，也不绕过保存校验。
- 调整目标大小后保留旧预览并标记过期；未重新确认的结果不可入库。分析、试切和生成均可停止。

## 几何与存储边界

现有模块占地是矩形，接口必须位于矩形的北、东、南、西四边。第一版仍遵守这些规则，保持 `.X`、`connections`、`footprint` 格式兼容。

- 自动选择的是水平或垂直切线；不生成斜向接口或任意多边形占地。
- 弯道、岔路尽量保留在一个矩形里；如果包围矩形圈入了其他不连通通路，不能仅通过选中“主通路”让它通过校验。
- 找不到合法矩形拆法时保留大块并说明原因。禁止通过擦图、移动素材、填碰撞、封路或忽略通行小岛强行通过。
- 分区覆盖源分析范围，各格子归属唯一；未入库的块仍在预览中显示，不把“已分区”误称为“全部可用”。
- 合并仅允许合并后仍为矩形、没有漏格或额外吞入未选择块的组合。不能直接把 L 形组合当作矩形保存。
- 已知对象实例和用户标记区域可作为切线保护区；没有对象元数据时，不能保证自动识别图片中的完整建筑。

任意形状的模块占地、旋转、自动补墙和改写源地图碰撞均不属于本轮。若真实地图证明矩形模型无法表达需要的模块，应单独评估存储与放置模型扩展，不在本轮暗中改变格式。

## 实施阶段

### 阶段 17：地面兼容性与可定位诊断

1. 用最小合成样例复现“非绘制格保留地面引用导致模块被拒绝”，并对 `632.map` 建立只读回归案例。
2. 核对地面有效图片、裁剪偏移和放置偏移语义，修复兼容性判断。保留有效地面图片和所有碰撞，不直接清理整个 `.map`。
3. 将地面对齐错误细分为结构化诊断，给出对应格子与当前来源；不解析报错字符串推断原因。
4. 提取模块专用通行规则，供模块分析、接口校验和生成使用。普通 `MapCheck` 当前采用不同的邻接和碰撞规则，本轮不顺便改变普通地图检查功能。
5. 分色显示四邻域通行区域及孤岛。点击错误可定位，展示失效的确切原因。

验收：偶数地面、旧地图冗余引用、负局部坐标、裁剪和平移后显示正确；源文件哈希及碰撞矩阵不变；保存重开图像和通行结果一致。没有完成兼容性验证前，不把“全部失败”归类为通道识别失败。

### 阶段 18：按通道提出合法矩形分区

1. 建立通行掩码和连通区域，计算距墙距离及局部通道宽度，找窄口、较直段、弯道与分叉候选区。
2. 通道骨架或方向估计只用于候选排序，最终结果始终使用完整四邻域掩码校验，不能用近似图替代可达性验证。
3. 在当前矩形中枚举有限数量的水平／垂直候选切线。优先窄且稳定的通路横截面，避开分叉中心、急弯和保护区；目标模块大小作为参考。
4. 以有限搜索形成矩形分区树：允许分析过程中存在尚待细分的无效节点，但只有最终通过校验的叶子可入库，不能要求所有中间节点都已经是合法模块。
5. 一次切口同时生成两侧接口，检查两侧边界、向内一格、类型、宽度、奇偶位置和接口数限制；无需用户反复把两侧分别调成同样的宽度。
6. 局部无法拆分时停止继续细切，保留候选和失败证据。搜索次数、候选数量与内存均设上限；停止不留下可保存的半成品。

验收：直道、L/S 弯、T/十字岔路、尽头、环路、平行通道、不同宽度和近邻孤岛；不存在重叠、丢格、越界或接口漂移。对 `632.map` 比较修复兼容性后的固定网格基线，报告可用块、接口匹配、分块大小及需要人工处理的区域，不只比较数量。

### 阶段 19：候选选择和人工调整

- 点选模块后高亮边界和接口；勾选框只控制入库选择。
- 在当前模块上添加水平／垂直切线；移动切线时显示双侧预览并吸附到合法地面网格。
- 合法预览显示即将产生的模块和成对接口；非法切口显示红色虚线及原因，不覆盖最后一次有效结果。
- 提供相邻模块合并、保护区域、撤销／重做和 Esc 取消。失去指针捕获时取消未完成拖动，一次拖动是一条历史操作；文本框快捷键保持文本编辑行为。
- 模块稳定标识与列表序号分离，局部调整不随意清空其他模块的选择；受影响邻居的接口同步重算。
- 参数变化、撤销及失败不会悄悄丢弃选择或把过期预览保存入库。

验收：真实鼠标／键盘事件覆盖添加、反向拖动、移动、合并、保护、取消、撤销与列表联动；缩放平移后切线和接口仍贴合格子；截图核对高亮与错误位置。

### 阶段 20：入库和随机生成验收

- 复用现有 `SaveBatch` 事务、目录写锁和回滚能力；只保存用户勾选且通过最终校验的模块。
- 模块前缀命名不再依赖固定网格行列，避免自适应分区重名或跳号造成误解。
- “入库并随机生成”仅使用本批模块；显示可匹配接口及当前实例数量是否得到完整结果。已有一对匹配接口不代表一定可以生成任意数量。
- 沿用独立新地图、自适应尺寸、种子复现、整体撤销和保存重开，不添加另一套生成器。

验收：真实地图副本完成分析 → 选择与调整 → 入库 → 生成 → 创建新地图 → 撤销／重做 → 保存重开。源文件及已有模块不被覆盖；失败和取消可回滚。真实数据未通过时保留问题记录，不以合成测试替代真实验收。
